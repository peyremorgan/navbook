## Where it stands

- Nothing in `packages/web/app` guards a way out. A search for `onBeforeRouteLeave|onBeforeRouteUpdate|beforeunload` finds nothing, and no draft is kept in storage: `sessionStorage` holds only the token (`plugins/02.auth.ts:29`) and the filter memory (`composables/useFilterMemory.ts`).
- `components/MarkdownBody.vue:29-36` already describes the gap and leaves the guard to "whatever page owns the unsaved work". No fix has landed since, and no branch or PR addresses it.

## A second way out: an expired session during Save

`plugins/03.apollo.ts:78-84`:

```ts
if (isUnauthenticated(failure)) {
  void auth.forget().then(() => auth.login());
  return;
}
```

If the token is refused, for example because silent renew failed, clicking **Save** sends the mutation, receives UNAUTHENTICATED and does a full-page `signinRedirect`. `auth.login()` returns to the current URL, but the component state, and so the draft, is gone. This case is worse than a stray click because the person did what they were supposed to do. Any fix needs to decide what happens to the draft here. A simple option is to write dirty drafts to `sessionStorage` under the page's route and restore them on mount.

## Acceptance cases

- [ ] Given a spec in edit mode with a changed body, when the sidebar "Issues" link is clicked, then a confirm dialog appears. Cancel keeps the editor and its text. Confirm navigates away.
- [ ] Same as above for a reference link clicked in the SpecEditor **Preview** pane (`MarkdownBody.follow`) and for the breadcrumb.
- [ ] Same for a non-empty CommentForm, a non-empty ReviewForm, an open EditableText whose draft differs from the value, and `/issues/new` with any field filled.
- [ ] Given unsaved work, when the tab is closed or reloaded, then the browser's `beforeunload` prompt shows.
- [ ] Given an editor opened with **no** changes, or a draft just saved successfully, navigating away shows no prompt.
- [ ] Moving between routes that share a page component (e.g. `/issues/a` → `/issues/b` via a link in the body) is guarded too. That needs `onBeforeRouteUpdate`, not only `onBeforeRouteLeave`.
- [ ] Given a draft and a Save refused as UNAUTHENTICATED, after signing back in the draft is still there, or the person was told it would be lost before being redirected.
- [ ] The existing e2e suite stays green. The guard must not fire on the app's own post-save navigations, such as `/issues/new` → the created issue.

## Size of the fix

Small to medium. One `useUnsavedGuard(isDirty: () => boolean)` composable that registers `onBeforeRouteLeave`, `onBeforeRouteUpdate` and a `beforeunload` listener, used by the five owners above, plus a Playwright spec for the cases. The 401-on-save case adds a draft-persistence step.
