Confirmed on `dev` (1e09e0f) against the built bundle with the Playwright stack.

**Repro**

1. Open a pull request, e.g. `/prs/bbbb0001` in the e2e fixture.
2. Click **Commits**: the commit table shows.
3. Click **Changes**: the diff shows, **and the commit table stays visible above it**.
4. Click **Conversation**: the thread shows, **and the commit table and diff stay visible above it**.

A tab only goes wrong once its content has loaded. While it is still loading, it hides as it should.

**Playwright output** (a new test that clicks Commits → Changes → Conversation):

```
Error: expect(locator).toBeHidden() failed
Locator:  getByTestId('pr-commits')
Expected: hidden
Received: visible
  34 × locator resolved to <section class="space-y-3" data-testid="pr-commits">…</section>
```

**Cause**

`packages/web/app/pages/prs/[ref].vue` puts `v-show` on the `QueryState` *component* for the Commits and Changes panels:

```vue
<QueryState v-if="visited.commits" v-show="tab === 'commits'" …>
  <CommitTable v-if="commits" … />
</QueryState>
```

`v-show` only works on a component whose root is a single element. `QueryState` renders a `<div>` while loading, which `v-show` can hide. Once the data arrives it renders `<slot v-else />`, a fragment with no single root element, so Vue drops the directive (with a "Runtime directive used on component with a non-element root node" warning in dev builds). Panels stay mounted once visited, by design, so they then stay visible whatever tab is selected. They sit above the conversation grid in the template, which is why they show "at the top of the page".

The existing e2e tests check that the selected panel is visible, and that the conversation hides. None of them checks that the Commits or Changes panel hides again.

**Fix direction:** put the `v-show` on a plain wrapping element (a `<div>` around each `QueryState`) instead of on the component itself.
