## Confirmed on `dev` (1f34c63)

Reproduced with the checkout's own CLI (`node packages/cli/src/main.ts`) in a fresh repository made by `nav init`, rewriting only `.navbook/navbook.json` between runs:

```console
$ cat .navbook/navbook.json
{ "version": 1, "plugins": ["@navbook/plugin-kb"], "review": { "minApprovals": "two" } }
$ nav doctor
error  D15  .navbook/navbook.json: 'review.minApprovals' must be a whole number of at least 1
1 error, 0 warnings
nav: 1 format violation(s) found
(exit 2)

$ cat .navbook/navbook.json
{ "version": 1, "plugins": ["@navbook/plugin-kb"] }
$ nav doctor
No problems found.
(exit 0)

$ cat .navbook/navbook.json
{ "version": 1, "plugins": { "@navbook/plugin-kb": true } }
$ nav doctor
No problems found.
(exit 0)

$ cat .navbook/navbook.json
{ "version": 1, "plugins": null }
$ nav doctor
No problems found.
(exit 0)

$ git add -A && nav doctor --staged
No problems found.
(exit 0)
```

All three malformed shapes pass with exit 0, including under `--staged`, so the pre-commit hook lets them through as well. With a second fault present, only the `review` one is named.

### Where it happens

- `packages/core/src/core/validate.ts:724`: `checkMarker` reads only `repo.reviewPolicy.problems` and `repo.mergePolicy.problems`. Its doc comment (lines 715-720) still says "The two readings".
- `packages/core/src/core/tree.ts:200-202` and `:270-271`: `Repo` carries `reviewPolicy` and `mergePolicy`, and `parseTree` fills just those two from `markerText`.
- `packages/core/src/core/policy.ts`: `parseReviewPolicy` (line 63) and `parseMergePolicy` (line 175) are the only parsers.
- `packages/core/src/workspace/workspace.ts:184-197`: only `readReviewPolicy` and `readMergePolicy` exist.
- Nothing under `packages/*/src` mentions `plugins`, so this adds the first reading and does not conflict with any existing one.
- `doc/spec/fixtures/format/invalid/` holds `d15-review-policy/` and `d15-merge-policy/` only.

The spec on `dev` still requires the check: spec 04 line 531 (the D15 row names `plugins`) and line 560 ("one diagnostic per fault"), and spec 02 lines 684 and 711 (§2.12, "MUST be a JSON object … reported exactly as a malformed review policy is").

I'm taking it and will follow the implementation plan above.
