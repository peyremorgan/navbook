Three things that sharpen this.

**`parseTree`'s interface is not the problem and should not change.** Taking a flat `path → content` map is what lets it work "over a working tree, a git index, or the blobs of a branch that is not checked out", and `stagedRepo` and the cross-ref scan both depend on that. The caller is what should decline to fill in content nobody reads — and one caller already does it right: `scanRefsForOpenPrs` reads only what is under a pull request's own directory, via `lsTreeRecursive` plus a batched `cat-file`. This is that same instinct, missing from the filesystem path.

**The cost is not the 5 ms.** It is worth being precise about what the measurement does and does not show, so nobody dismisses it on the timing. The read itself is fast because the page cache is warm and the file is one contiguous read. What scales badly is: the UTF-8 decode (a real CPU cost, linear in bytes, and unavoidable once `readFileSync(..., "utf8")` is chosen over a `Buffer`), the resident memory, and the GC pressure of a multi-megabyte string per command. On the server, where the process is long-lived and `ctx.repo()` memoizes per request, a large extension namespace is held for the life of every request that touches the tree.

**Plugins are the reason this stops being hypothetical.** Today `.navbook/` holds only what Navbook writes, so `reserved` is nearly always empty and this costs nothing — which is exactly why it has never shown up. The `plugins` work turns "an uninterpreted top-level directory" from a thing nobody has into a thing the format advertises. Fixing it before the first plugin ships is much cheaper than after, because afterwards any change to what gets read is a behaviour change somebody may have come to rely on.

Possibly related: there is an open report that some GraphQL queries take several seconds on the deployed tracker. I have not established a connection — that tracker has no extension namespaces, so `reserved` should be empty there and this would not be the cause — but if anyone is profiling `loadRepo`, the two want looking at together.
