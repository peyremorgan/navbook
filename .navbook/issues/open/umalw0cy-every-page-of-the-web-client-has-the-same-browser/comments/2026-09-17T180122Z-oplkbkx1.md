Confirmed against the built client, which is what gets deployed.

`packages/web/dist/index.html` — the one shell `nuxi generate` emits and every route is served — carries the title inline:

```html
<meta name="viewport" content="width=device-width, initial-scale=1"><title>Navbook</title>
```

Because the package is `ssr: false`, that shell is handed out unchanged for `/issues`, `/issues/:ref`, `/prs/:ref` and every other address, so the title is identical before any JavaScript runs. Nothing then changes it: grepping the emitted bundle for head management finds no `useHead` call at all, only unhead's own empty default record —

```console
$ grep -ohE '.{40}(useHead|titleTemplate|\btitle:)' packages/web/dist/_nuxt/*.js
,link:[],style:[],script:[],noscript:[],title:
```

every other `title:` hit is a Nuxt UI component prop or an `AuthNotice`, not the document title. Same on the source side: `useHead` and `useSeoMeta` appear nowhere under `packages/web/app/`, in any of the thirteen pages or in `app.vue`.

## Repro steps

1. `pnpm --filter @navbook/web dev:stack`, then open <http://localhost:3000> and sign in.
2. Open an issue from the listing, then a pull request, then **Features**.
3. Read the browser's history (`Ctrl+H`): four entries, all called `Navbook`, distinguishable only by their URL.

Nothing in the suites covers this, so the fix wants a test: no assertion on `document.title` exists in `packages/web/test/` or `packages/web/test-e2e/`.
