## Code

- `packages/cli/src/commands/install.ts:92-102`: `if (current === "true") note else set`. Any other value, including `false` or `conflict`, is overwritten without a word.
- `packages/cli/src/commands/install.ts:148-155`: `if (readLocal(...) !== null) unset`. The alias path (`:136-143`) only unsets when the value is `!nav`.
- `packages/core/src/git/config.ts:24-34`: `readLocal`/`setLocal`/`unsetLocal`. Nothing records that `nav` wrote the value.

## Acceptance cases

- [ ] Given `merge.directoryRenames=conflict` (or `false`), when `nav install --merge-config -y` runs, then the value is left alone and a note names it, as the alias does ("already set to "conflict"; leaving it alone"). Or, if we decide to replace it, the plan line shows the old value.
- [ ] Given `true` set before `nav install`, when `nav uninstall --merge-config -y` runs, then the value stays.
- [ ] Given `nav install` set `true`, when `nav uninstall --merge-config -y` runs, then the key is unset.
- [ ] Given `merge.renames=false` or `diff.renames=false` (with no `merge.renames`), when `nav install` runs, then the plan or notes say that directory-rename detection is off and `merge.directoryRenames` has no effect. `nav doctor` warns the same way.

## Fix size

Small, about 40 lines plus tests in `packages/cli/test/cli/install.test.ts`. The only design point is how `uninstall` knows that `nav` wrote `true`. `git config --comment "nav"` (git ≥ 2.45) could tag the entry, a `navbook.*` marker key would also work, or `uninstall` could only unset when the value is `true` and accept that a pre-existing `true` still gets removed. For (3), read `git config --get merge.renames`, falling back to `diff.renames`.
