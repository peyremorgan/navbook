## One thing to add to the plan

The D10 fixture doesn't need `history:`. The single-commit form `init: {from: tree, date: …}`, which D5 and D6 already use, sets the commit date the same way. An `issue.md` with `created:` a year before that `date` is enough to cover it. Also, `test/conformance/harness.ts:382-406` compares `expect.diagnostics` as an exact list, not a subset. So in the invalid case, listing only the D10 entry also asserts that nothing else fires, and the valid counterpart can use `diagnostics: []`, as `format/valid/merge-policy` does.
