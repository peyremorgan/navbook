Context, so this is not read as an argument against writing the spec first.

The implementation does exist in this clone — it is on another branch:

```console
$ git worktree list
/…/navbook                            2ebc8ce [dev]
/…/navbook/.claude/worktrees/plugins  74952b0 [worktree-plugins] locked

$ git stash list
stash@{0}: On dev: plugin leftovers on dev, superseded by worktree-plugins (2026-09-20)
```

What landed on `dev` is the documentation, in commit `780c315` `doc(spec): reserve extension namespaces and specify plugins`. So this is a release-hygiene issue about what `dev` says, not a design problem — and the split is a perfectly normal consequence of specifying before building, which is the order this project deliberately works in.

The part worth keeping separate is **which of the six documents is allowed to be ahead**. There is a real line here and the project already draws it elsewhere:

- **Format documents may be ahead, and should be.** Spec 02 §2.12 reserves namespaces so that a tool without the plugin still preserves the plugin's data. That only works if it is specified *before* anybody writes such data. Same for the `plugins` key in §2.10.
- **Tool documents may not.** Spec 04 §4.3's `nav plugin` section and spec 05 §5.2's package list describe this repository. `doc/spec/06-future.md` exists precisely to hold reserved tool behaviour, and it already demonstrates the marker: §6.3 is headed "Web client (built)" and its preamble explains that it stayed in the reserved chapter because that is where the argument lives. A `nav plugin` section marked the same way in either direction would be unambiguous.
- **The README may not, at all.** It is the zero-context document and it is the one currently printing a transcript of a failing command.

D15 not reading the `plugins` declaration is filed separately, because that one is a format check a conforming tree is judged by and is worth closing on `dev` whichever way this goes.

Full write-up: `doc/audit-report/04-documented-plugin-surface-does-not-exist.md` in the working tree.
