## Confirmed on `dev` at 1f34c63 (2026-09-27)

Everything the issue describes still holds a week later, with `@navbook/cli` now at 0.4.0.

```console
$ node packages/cli/src/main.ts --version
0.4.0
$ node packages/cli/src/main.ts plugin install
error: unknown command 'plugin'
...
$ echo $?
1
$ node packages/cli/src/main.ts plugin list      # same error, exit 1
$ ls packages/
cli  core  server  web
$ grep -rn '"plugins"\|plugin' packages/core/src packages/cli/src
(no matches)
```

Features are still implemented natively, in `packages/core/src/ops/feature.ts` and `packages/cli/src/commands/feature.ts`. `worktree-plugins`, the branch named in the first comment, is not in this clone (`git branch -a --list '*plugin*'` is empty), so nothing here is about to land the tooling. That settles the direction the implementation plan already chose: mark the tool-facing passages as reserved.

## Passages the plan does not list

Checking every `plugin` mention under `README.md` and `doc/` turned up four more present-tense claims about things that do not exist on `dev`:

| Where | Claim | Reality |
|---|---|---|
| `doc/spec/05-implementation.md` §5.2, the **Plugins:** bullet (lines 63–72) | "a plugin is one npm package … A plugin receives the host's own `@navbook/core` … declares the plugin API version" | no loader, no host, no API version anywhere in `packages/` |
| `doc/spec/04-cli.md` §4.4 (line 608) | "No plugin code loaded for a command whose declaration does not name it" | trivially true today, but it points at the §4.3 rule, so it should carry the same marker |
| `doc/plugins.md` "Available plugins" (line 63) | links `../packages/plugin-kb/README.md` | broken link (so is `README.md:354`, which the plan does cover) |
| `doc/plugins.md` "The code" / "Developing one" | `import type { CorePluginHost } from "@navbook/core"`, `NAVBOOK_PLUGIN_PATH`, `NAVBOOK_WEB_PLUGINS`, and "set `NAVBOOK_PLUGINS` in `.env`" | none of the four names occur in `packages/`, `.env.example` or `compose.yaml` |

The plan's banner on `doc/plugins.md` covers the last two rows, as long as the banner names them. The §5.2 bullet needs the same treatment as the "fifth package" sentence beside it.

One wording change to the plan: its spec 04 marker says "not a command in @navbook/cli 0.3.0". The version has already moved on, so the marker should say "the reference implementation does not yet provide" and name no version. Otherwise it goes stale on the next release, whether or not the feature lands.
