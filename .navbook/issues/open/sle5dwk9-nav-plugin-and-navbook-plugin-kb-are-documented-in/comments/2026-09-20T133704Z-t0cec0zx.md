## Implementation plan

Decision taken: **mark the tool-facing sections as reserved on `dev` now**, rather than waiting for `worktree-plugins` or rewriting the documentation to describe only what exists. Six passages, four files, no code.

The line being drawn — worth stating in the commit message, because it is the rule that should survive this issue:

- **Format documents may be ahead, and should be.** Spec 02 §2.12 reserves the namespaces so a tool without a plugin still preserves that plugin's data. That only works if it is specified before anybody writes such data. Nothing in §2.10 or §2.12 changes.
- **Tool documents may not.** Spec 04 §4.3 and spec 05 §5.2 describe this repository.
- **The README may not at all.** It is the zero-context document, and it is currently printing a transcript of a failing command.

### 1. `doc/spec/04-cli.md` — the `nav plugin` section (lines 103–156)

Keep the section where it is and in full: the design is argued there and the argument is the useful part, exactly as `doc/spec/06-future.md` §6.3 explains for the web client. Add a marker paragraph directly under the heading:

```markdown
### Plugins — `nav plugin <verb>` (reserved)

> **Reserved.** This section specifies a surface the reference implementation
> does not yet provide: `nav plugin` is not a command in @navbook/cli 0.3.0.
> What [02 §2.12](02-data-model.md) reserves — the namespaces and the `plugins`
> declaration — *is* in force, and a tool must already preserve data it finds
> there. This section describes how a machine comes to have a plugin, and is
> the contract the implementation will be held to when it does.
```

The inverse of §6.3's "(built)" marker, and readable the same way. Also amend the sentence in §4.3's preamble that currently reads as present tense — "A tool MAY let an extension … add to this command tree" is already conditional and can stay — and the `--help`/completion performance requirement in that section, which is a claim about a budget nothing is currently measured against.

-  the implementation of features and specifications ([02 §2.11](02-data-model.md)):

-  It is what proves the plugin surface is enough to build with, since it uses
