Confirmed on `dev` at `ae9aac5`, and there is a second failure behind the first.

## 1. The build stage (as described)

```console
$ docker build --progress=plain -f packages/server/Dockerfile .
#21 13.33 src/cli/index.ts(14,36): error TS2307: Cannot find module '@navbook/cli/plugin' or its corresponding type declarations.
#21 13.33 src/core/files.ts(10,35): error TS2307: Cannot find module '@navbook/core' or its corresponding type declarations.
#21 13.33 src/server/index.ts(23,51): error TS2307: Cannot find module '@navbook/server/plugin' or its corresponding type declarations.
#21 13.39 [WARN]  Local package.json exists, but node_modules missing, did you mean to install?
```

Core and server pack fine; plugin-kb's `prepack` (`tsc -p tsconfig.build.json`) fails. Two causes, both in the build stage:

- `packages/server/Dockerfile:35` selects `@navbook/server...`, which never reaches plugin-kb (it depends on the server, not the reverse).
- plugin-kb's `src/cli/index.ts:14` does `import type { CliPluginHost } from "@navbook/cli/plugin"`. In the workspace that export is `./src/plugins/host.ts`, so `tsc` needs cli's sources, and the stage copies only `packages/cli/package.json`.

## 2. The runtime install, with `NAVBOOK_PLUGINS=@navbook/plugin-kb`

With the build stage fixed, the empty-plugins build succeeds but the plugin-kb one fails at the final `npm install`:

```console
npm error ERESOLVE unable to resolve dependency tree
npm error Found: vue@2.6.14
npm error   peer vue@"^2.6.0 || ^3.1.0" from @vue/apollo-composable@4.2.2
npm error     peerOptional @vue/apollo-composable@"^4.2.2" from @navbook/plugin-kb@0.4.0
npm error   peer vue@">= 2.5 < 2.7" from @vue/composition-api@1.7.2
npm error     peerOptional @vue/composition-api@"^1.0.0" from @vue/apollo-composable@4.2.2
npm error Could not resolve dependency:
npm error peerOptional vue@"^3.5.40" from @navbook/plugin-kb@0.4.0
```

npm resolves plugin-kb's *optional* web peers even though it installs none of them, and `@vue/apollo-composable`'s own optional `@vue/composition-api` peer pulls it to a Vue 2. Bisected by editing the tarball's manifest: dropping either the `vue` or the `@vue/apollo-composable` peer makes the install pass, and so does `--legacy-peer-deps` (after which nothing Vue is on disk). `npm install core.tgz plugin-kb.tgz` alone fails the same way, so this is npm against plugin-kb's manifest, not the Dockerfile. `nav plugin install` hit the same thing earlier and passes `--legacy-peer-deps` for it (`packages/cli/src/plugins/store.ts:130-140`, with a test in `packages/cli/test/cli/plugins.test.ts`).

## Web image

`docker build -f packages/web/Dockerfile .` succeeds on `dev` with `NAVBOOK_WEB_PLUGINS` empty; this issue is the API image only.

## Plan

In the build stage, select `@navbook/plugin-kb...` too and copy `packages/cli` whole. In the runtime stage, pass `--legacy-peer-deps` for the same reason the CLI does. Add tests under `test/deploy/images.test.ts` that every packed package's workspace dependencies are both installed and copied as sources.
