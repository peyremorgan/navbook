**Planned fix**, working on `fix/u0a6u6ev-scan-only-parsed-blobs`:
1. `core/tree.ts` exports the set of paths `parseTree` may read: the marker, each entity file and its comments, and registered extension locations. It is computed by `classify` itself, so the directory grammar keeps a single owner, which was the concern with option 2. A contract test pins that `parseTree` never asks a tree for a path outside that set.
2. `scanRefsForOpenPrs` runs one `ls-tree -r` of `prs/open` per ref, and one `cat-file --batch` for all refs together, containing only those paths. That is refs + 2 git processes instead of refs × (1 + 2 × PRs).
3. `catBlobs` throws on a spawn error, a non-zero exit or `ENOBUFS`, naming the cause. A missing object still just leaves its entry out.
