Implemented. `parent` and `subtasks` are frontmatter keys on `issue.md`, written on both sides at once by `nav issue open --parent`, `nav issue link` and `nav issue unlink`; depth is unbounded. `nav issue show` names the parent and, with `--depth`, the subtask tree beneath it. Two doctor checks: D11 when the sides disagree, D12 when the parent chain loops. `doctor --fix` mends what the tree can settle and consults git history for a subtask two issues claim, declining rather than guessing when history is silent or a claim names an issue this tree does not hold.

Beyond the ticket: `nav issue delete` severs the links it would otherwise leave dangling, and `--recursive` takes the whole subtree in one commit.

Specified in 02 §2.5 and 04 §4.3, with conformance fixtures for each verb and both checks.
