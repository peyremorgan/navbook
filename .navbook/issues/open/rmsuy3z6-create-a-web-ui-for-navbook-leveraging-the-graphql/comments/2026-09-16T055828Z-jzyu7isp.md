Assessed against the code and the history on `dev`. This is done — the web client exists, ships, and is covered by CI.

## Scope, item by item

**New client app consuming the GraphQL API** — delivered as `packages/web` (`@navbook/web` 0.2.0), a Nuxt 4 single-page bundle built with `nuxi generate`, talking to `@navbook/server` through Apollo. 46 commits touch it, starting at `91b8160 feat(web): scaffold the Nuxt client and its generated types` and running through `6c59a57` on `dev`.

**Core views** — all present:
- Issues in full: listing with a URL-borne filter (`pages/issues/index.vue`, `EntityFilterBar`), detail with comments and the subtask tree (`pages/issues/[ref].vue`, `CommentCard`/`CommentForm`/`SubtaskTree`), filing (`pages/issues/new.vue`), in-place editing of every field, closing with a resolution, reopening, linking/unlinking.
- Pull requests: listing, detail with revisions, comments and reviews bound to a revision, reviewers and the decision they add up to (`pages/prs/index.vue`, `pages/prs/[ref].vue`).
- Label/assignee/milestone management: editable in place on an issue — `LabelEditor` and `FieldEditor` cover Labels, Assignees, Features, Milestone, Rank and Deadline.
- Beyond the original scope, since: an inbox, features and spec documents with a preview editor, rank/deadline ordering with drag-to-reorder, per-listing filter memory, a people directory behind every person menu, and a theme that follows the browser.

**No direct filesystem access** — holds. Nothing under `packages/web/app` or `packages/web/src` imports `node:fs`; every read and write goes through the schema, with types generated from it by `graphql-codegen` into `src/generated/gql` and a `codegen:check` script that fails on drift.

**Out-of-scope items stayed out** — no subscriptions. Auth is PKCE OIDC against whatever provider `config.json` names, i.e. only what the server already provides; the authorization policy beyond that is #gkbu9yhp.

## Verification

## One delta worth a follow-up

A pull request is read and reviewed, not edited. `pages/prs/[ref].vue` exposes only `reviewers` for editing (the comment at `saveReviewers` says so deliberately); its Labels, Assignees and Milestone are rendered read-only. But `UpdatePrInput` in `packages/server/schema.graphql` accepts `title`, `body`, `labels`, `assignees`, `milestone` and `features` as well, so the gap is in the client, not the API — which makes `packages/web/README.md`'s claim that "updating ... a pull request" is absent because "the API does not expose them" inaccurate for the patchable fields.

Opening and merging a pull request genuinely are absent from the API, so those stay out.

Suggested next step, as its own ticket rather than a reason to hold this one open: widen the pull request sidebar to the fields `updatePr` already takes, and correct that README paragraph to separate "the API does not expose it" (open, merge, delete) from "the client does not offer it yet" (labels, assignees, milestone, features, title, body).

Closing as fixed.
