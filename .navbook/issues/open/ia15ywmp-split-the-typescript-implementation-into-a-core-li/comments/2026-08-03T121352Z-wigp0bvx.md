Done in 6de26a2. The repository is now a pnpm workspace of @navbook/core (the whole implementation: format logic, git plumbing, workspace I/O, and an ops layer holding the verbs) and @navbook/cli (argument parsing, $EDITOR, prompts, rendering). The API server behind the web client becomes a second consumer of the library rather than a fork of the CLI.

Three things worth knowing for the next ticket:

pnpm is load-bearing, not a preference. core's exports point at its TypeScript sources so the workspace needs no build step, and publishConfig.exports rewrites them to dist/ at pack time. npm implements neither that nor the workspace: dependency rewrite, so a guard refuses to pack or publish either package with it.

Operations that stop to ask are plan/execute pairs rather than callbacks, so a server can render the plan, take the answer over HTTP, and then execute. Identity is an input to the context, which is what lets the gateway of §6.2 commit with the web user as author.

Provenance had never actually worked: 0.1.2 was published with --provenance but carries no attestations, because npm needs a repository field and neither package declared one. Both do now, and the release packs with pnpm then uploads with npm.
