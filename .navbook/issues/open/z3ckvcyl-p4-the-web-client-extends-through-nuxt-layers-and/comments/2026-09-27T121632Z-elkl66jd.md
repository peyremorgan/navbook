**Current state**
- `packages/web/nuxt.config.ts` sets `modules: ["@nuxt/ui"]` and has no `extends`. `NAVBOOK_WEB_PLUGINS` appears only in docs (`grep -r NAVBOOK_WEB_PLUGINS packages` finds nothing).
- There is no slot registry. The places P6 would move into slots are hard-coded today: `app/layouts/default.vue` (the Features nav link), `app/pages/features/**` (about 470 lines), `app/components/FeatureRow.vue`, `app/composables/useFeatureMutations.ts`, `app/components/EntityFilterBar.vue` and `app/utils/filter-params.ts` (the feature filter), `app/pages/issues/new.vue` (the feature field), and the feature fragments in `app/graphql/*.ts`.

**Acceptance cases**
- [ ] `NAVBOOK_WEB_PLUGINS="" pnpm --filter @navbook/web build` produces the same output as today, and the existing e2e suite passes.
- [ ] `NAVBOOK_WEB_PLUGINS="<fixture>"` adds the fixture layer's page at its route and its nav link through the `nav-links` slot.
- [ ] Each slot (nav links, entity detail panel, create-form field, filter chip, row badge) renders what a fixture layer registers, in order, and renders nothing when no layer registers anything.
- [ ] A layer that registers into an unknown slot fails the build with a message naming the layer. It is not silently ignored.
- [ ] Naming a plugin that has no `./web` export, or one that is not installed, fails the build and names the plugin.
- [ ] The built bundle still reads `public/config.json` at boot. Plugins do not add build-time API addresses.
