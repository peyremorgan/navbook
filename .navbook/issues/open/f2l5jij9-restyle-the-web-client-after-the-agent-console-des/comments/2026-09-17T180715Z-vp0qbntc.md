## How Nuxt UI takes a palette

Worth knowing before touching it, because the obvious route (`ui.colors.primary: "#B87A45"`) does not exist:

- `ui.colors.<role>` in `app.config.ts` names a *scale*, and the runtime plugin (`@nuxt/ui/dist/runtime/plugins/colors.js`) emits `--ui-color-<role>-50…950: var(--color-<name>-<shade>)`. A name that is not a Tailwind colour works as long as `@theme static { --color-<name>-50…950 }` defines it in our CSS; `static` because the shades are read through `var()` and would otherwise be tree-shaken.
- The same plugin sets `--ui-<role>` to the 500 shade in light and the 400 in dark, inside `@layer theme`. Our light theme needs the 600 for text, so `main.css` overrides `--ui-primary` and friends per theme, outside any layer, which wins over the layered defaults.
- Surfaces and text (`--ui-bg`, `--ui-bg-muted`, `--ui-bg-elevated`, `--ui-bg-accented`, `--ui-text*`, `--ui-border*`) are set per `.light`/`.dark` class the same way. The console's ladder is not evenly spaced, so these are set by hand rather than derived from the neutral scale.
- `--ui-radius: 0px` zeroes every `rounded-*` utility, since Nuxt UI derives `--radius-sm…3xl` from it.
- `UButton` only wraps its `label` *prop* in the label span (`Button.vue:151`); words written in the default slot, which is every button here, are not. A font override for buttons therefore goes on the `base` slot.

## Contrast, measured

Using the console's own values as text on its own surfaces, with the WCAG 2.x formula:

| text | on `--bg` #0E1420 | on `--card-bg` #18222F | on `--agent-bg` #1C2735 |
|---|---|---|---|
| `--fg` #C9D2DE | 12.07 | 10.51 | 9.89 |
| `--muted` #8A97A8 | 6.21 | 5.40 | 5.08 |
| `--dim` #5C6979 | 3.29 | 2.87 | 2.70 |
| `--accent` #B87A45 | 5.18 | 4.51 | 4.25 |
| `--s-done` #5E9C7A | 5.71 | 4.98 | 4.68 |
| `--s-run` #5B7FA6 | 4.41 | 3.84 | 3.62 |
| `--s-blocked` #B25C5C | 4.02 | 3.50 | 3.29 |

On a TV wall nothing of that matters — the console has 8 px chips and nobody reads `--dim` text up close. Here it does. So each hue keeps the console value at 500 for fills and borders, and text takes a lighter 400 on dark and a darker 600 on light:

| hue | 400 (dark text) | worst dark surface | 600 (light text) | worst light surface |
|---|---|---|---|---|
| copper | #C98F5A | 5.44 | #8A5628 | 5.05 |
| sage | #6BA787 | 6.0 | #356B4E | 5.17 |
| steel | #7A9CC0 | 5.28 | #375A80 | 5.92 |
| brick | #D07C7C | 4.62 | #9A4040 | 5.47 |

The light surfaces are #F7F8FA / #EFF2F6 / #E6EAF0 / #D6DCE5 with text #1B2534 and muted #5C6979 (4.64 on the elevated one). "Dimmed" is Nuxt UI's placeholder colour and, it turns out, the colour of a `USelectMenu`'s placeholder — which for the filter menus is the control's only label. It has to pass too: #808D9E dark, #5E6C7D light.

## Plan

1. Vendor `saira-condensed` 500/600/700 and `ibm-plex-mono` 400/500/600 (latin + latin-ext woff2, ~200 KB, OFL) under `public/fonts/`, with `@font-face` in `main.css` and a preload for the two first-paint faces.
2. `main.css`: the four scales and the navy ladder in `@theme static`, the `--ui-*` tokens per theme, `--ui-radius: 0px`, a 15 px root size (mono is wider), a 1 px accent `:focus-visible` outline, and named utilities for the idioms: `page-title`, `pane-title`, `eyebrow`, `label-display`, `shimmer`.
3. `app.config.ts`: the colour mapping and slot overrides — display face on buttons, badges, alert and modal titles, form-field labels; no shadow on anything that floats; square avatars.
4. Components: nav as a segmented control with a filled active segment; status and sort chips the same; a 3 px status edge on issue, PR and inbox rows; `StatusBadge` outlined with the console glyphs; section headings as pane titles over a 2 px rule; sidebar names as eyebrows; comment cards on the surface ladder.
5. `statusColor`: OPEN → info, MERGED → success, CLOSED → neutral, and the unit test with it.
6. A `design.spec.ts` that proves the fonts render, the corners are square, and — the part that matters — walks every text node on seven views in each scheme and asserts the composited contrast. Its first run found exactly one thing the tokens had not: the placeholder colour above.
