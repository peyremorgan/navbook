Done on `feat/z9yqtsbv-plugin-tests`, closed with the work so the close reaches `dev` when the pull request merges. Every subtask is closed.

A final review of the whole diff found real problems, and they are fixed in the last four commits:

- **Symbolic links.** Core's `applyOps` followed them. A link pushed beside a run could have redirected an attachment upload from the API into the server's `.git/`. Writes and moves below the Navbook root now refuse a link.
- **Plan editor.** The web editor composed a plan from fields and silently dropped text the grammar could not read. It now refuses such a plan and names the faults. It also judges a save against the version it opened.
- **Interactive walk.** It ended the session, and lost its commit, when an answer read as a heading. It now asks again. It never walks past the steps a run followed, and says when it falls back to today's plan.
- **Outcomes.** A run's outcome now comes from one helper everywhere. The spec states that a pull request's tested state reads only its own files.
- **`plan-sha`.** It is hashed through git's filters, so it names the committed blob under `core.autocrlf`.
- **Smaller fixes:** JSON identity fields can no longer be overwritten by frontmatter, the API caps attachment reads at 20 MiB, the tested commit must be a plain revision, the web client now shows refusals it used to swallow, and multi-line sections are indented in `nav test show`.
