Implemented on `feat/s86nic83-plugin-chat`, stacked on #kw6afa4a's branch.

- **Engine:** zero-dependency OpenAI-compatible streaming client. It tolerates server quirks: no delta index, repeated or empty names, object arguments, and `tool_choice` is never sent. Nine tools are checked against their JSON Schema before running. The runner reads at once, asks before each write, or defers it to the next turn. The system prompt is `doc/assistant.md`.
- **CLI:** `nav chat` (REPL) and `-m`, with `-y` and `--json`; piped stdin is part of the question. Approved writes are committed, on a PR's own branch through the host's write sites. Verified in a real PTY: streaming, `Apply? [y/N]`, Ctrl-C stops a reply, Ctrl-C clears a line, Ctrl-D exits 0.
- **Server:** `Query.chat` and a stateless `chat` subscription over SSE. The transcript round-trips as an opaque string (the host's `JSON` scalar is output-only). Writes go through `host.api.execute`, and a browser disconnect aborts the model call (mutation-checked).
- **Web:** a bottom-right button opens a slideover with approval cards and the Edits selector (Manual / Allow all). Screenshots were checked in light, dark and at 390 px.
