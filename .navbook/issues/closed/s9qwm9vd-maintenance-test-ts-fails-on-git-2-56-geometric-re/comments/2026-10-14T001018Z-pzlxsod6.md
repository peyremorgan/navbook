## The change in git, from its source

The default task is `geometric-repack`. With no `maintenance.strategy`, `git maintenance run --auto` uses the geometric strategy: commit-graph, geometric-repack, pack-refs, reflog-expire, worktree-prune and rerere-gc. Each task runs only when its own auto condition holds.

**v2.55.0**, `builtin/gc.c`, `geometric_repack_auto_condition`:

```c
int auto_value = 100;
repo_config_get_int(the_repository, "maintenance.geometric-repack.auto", &auto_value);
...
/* too_many_loose_objects(auto_value): */
int auto_threshold = DIV_ROUND_UP(limit, 256) * 256;
return loose_count > auto_threshold;
```

The default is 100, rounded up to 256 loose objects. The test's 3000 cleared it by far.

**v2.56.0** moved the check into the files object-database backend (`odb/source-files.c`, `odb_source_files_optimize_required`, behind `geometric_repack_auto_condition` → `odb_optimize_required`):

```c
int auto_value = 6700;
repo_config_get_int(repo, "maintenance.geometric-repack.auto", &auto_value);
...
return loose_count > (DIV_ROUND_UP(((unsigned long) limit), 256) * 256);
```

The default is now 6700, rounded up to 6912. The key and the rounding are unchanged; only the default moved. That's the release note's "adjusted to match that of 'git gc --auto'". `gc.auto` is not read by the geometric repack, which is why setting it had no effect in the reproduction. It is read by the `gc` task (git's default before 2.54 made the geometric strategy the default, and still `maintenance.strategy=gc`) and by the incremental strategy.

## Where the test meets it

`packages/server/test/unit/maintenance.test.ts:264`:

```ts
const env = {
  ...process.env,
  GIT_CONFIG_COUNT: "3",
  GIT_CONFIG_KEY_0: "maintenance.auto",
  GIT_CONFIG_VALUE_0: "false",
  GIT_CONFIG_KEY_1: "maintenance.autoDetach",
  GIT_CONFIG_VALUE_1: "true",
  GIT_CONFIG_KEY_2: "gc.autoDetach",
  GIT_CONFIG_VALUE_2: "true",
};
...
// Enough that git's estimate — it samples one of the 256 object
// directories — clears its threshold whichever it samples.
for (let i = 0; i < 3000; i++) writeFileSync(join(dir, "files", String(i)), `blob ${i}\n`);
```

The comment's "its threshold" was git's default. Pinning `maintenance.geometric-repack.auto=100` in that env makes the threshold the test's own: 256, whatever git ships. Git keeps the key and the rounding in both versions, and a git without the key ignores it. The other maintenance tests (`test/server/maintenance.test.ts`) run a git shim for `maintenance run` and don't depend on the threshold.

`MAINTENANCE_ARGS` in `packages/server/src/maintenance.ts` is left alone. Git chose 6700 to stop "over-aggressive repacking during concurrent writes", which is the situation of the server's clone, so the server takes git's default.
