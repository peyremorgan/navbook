Landed across every layer. 177 cases added and five conformance fixtures; the suites now stand at 654 core, 302 CLI, 232 server, 272 web unit, 114 conformance, 63 deploy and 116 end to end, all green, and `nav doctor` is clean on this tree.

**Verified rather than assumed.** The two comparators are the part of this that could rot silently: nothing about the format ships to the browser, so the CLI and the client each spell §2.5's orders out and no compiler keeps them in step. `test/conformance/orders.test.ts` runs them against each other over four hundred rounds of colliding data — repeated ranks, repeated days, repeated timestamps — so every tier of every chain is reached and the tie-break at the end of each is exercised rather than skipped by luck.

**Four things this found that a unit suite could not.**

A `type="number"` input hands its component back a *number*, so the save handler threw a string method at it — and Vue swallows what an event handler throws, so the form closed on an edit that was never sent. Silent, and the worst shape a bug can take. It survived every unit test because the unit tests passed strings.

A row dropped on itself was placed at the end of the list: working out where it should go looked for it in the list it had already been taken out of, found nothing, and read that as "last".

The drag preview lied about the tail. A ranked row always sorts above an unranked one, so a row dragged past the last ranked row cannot land under the pointer — the write sends it back. `placeableIndex` now clamps the drop to where a rank can actually put it, so the preview and the arrow keys both stop at the end of the queue and what is drawn is what lands.

And `nav show` hid a `rank` on a pull request while showing a `deadline` beside it. `show` prints what a file carries rather than what its kind ought to have — both keys there are a D2 fault, and somebody reading one is reading it to find out what the file says.

**One thing removed.** Every order ends on "newest first", which core already computes, so `sortEntities` was split into the comparison and the sort and the CLI chains core's rather than its own copy. The browser keeps its copy and has to; that duplication is a property of the design, and this one was not.

**Left undone.** Two ranks that are already equal cannot be separated by a drop between them: there is no value between them, and the row lands adjacent, ordered by the tie-break. That is the case §2.5's note about leaving gaps is about, and it needs a hand-edit or a merge to reach.
