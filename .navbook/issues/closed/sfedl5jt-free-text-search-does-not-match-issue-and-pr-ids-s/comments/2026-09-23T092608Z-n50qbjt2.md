Confirmed and fixed. #x1nqfqsq, on `fix/sfedl5jt-search-ids`, targets `dev`.

The cause is the one suspected above: [`matchesText`](packages/core/src/core/query.ts)
never consulted `entity.id`, which was already on the record it was handed. The
fix matches a bare term as an anchored prefix of the directory name,
`<id>-<slug>`, from four characters, with an optional leading `#` — so one test
takes both the partial ID and a whole directory name pasted from a path, and
nothing shorter than four characters can reach an ID.

Every acceptance line above is met and covered: five unit tests in core, and one
end-to-end test in the browser, which is what actually proves the search box
rather than the query underneath it. `pnpm test`, `pnpm check` and the 152-test
Playwright suite are clean on a bundle rebuilt for the branch.

Two things the PR flags rather than hides. Spec 04 §4.3 described the old
behaviour, so this is a specification edit and not only a code fix — the row,
`nav list --help`, the README and the search box's placeholder all move
together. And comment IDs are still unsearchable: they are unique alongside
entity IDs under spec 02 §2.2 and a permalink carries one, but what a listing of
entities should do with a match inside a comment is a separate question from the
one reported here.
