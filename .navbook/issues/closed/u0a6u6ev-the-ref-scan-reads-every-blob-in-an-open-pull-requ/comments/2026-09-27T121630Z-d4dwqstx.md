**Also note:** the scan starts one `ls-tree` and one `cat-file` process per ref × per PR directory. So even after filtering, the process count grows as refs × open PRs. Batching all directories of a ref, or all refs, into one `catBlobs` call would fix that as well.

**Size of the fix:** option 2 (only request `pr.md` and `comments/*.md`) is about 10 lines. Option 1 (a batched lazy tree) is larger but could be shared with `j35o7oe4`. Either way, `catBlobs` should throw or report on a spawn error or ENOBUFS instead of returning `{}`.

**Acceptance**
- [ ] Given a branch whose open PR directory holds `pr.md` and `reports.json`, when `scanRefsForOpenPrs` runs, then the PR is found with `reports.json` in `extraFiles`, and `reports.json` is never in the `cat-file` request.
- [ ] Given the same PR on 3 refs, then plugin-namespace blobs are requested 0 times.
- [ ] Given a `catBlobs` failure (for example a stubbed spawn error), then the command reports an error and does not list "no PR here".
- [ ] Given a PR directory with a 300 MB `reports.json`, then `pr list --all-refs` still lists the PR on that ref.
