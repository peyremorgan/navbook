Confirmed on `dev` at 136a420, against the end-to-end fixture repository (`packages/web/script/fixture-repo.ts`) served by the built bundle.

**Repro**

1. `pnpm --filter @navbook/web build`, start the e2e stack (`startStack()` from `test-e2e/helpers/stack.ts`), sign in.
2. Open `/prs/bbbb0001` — a pull request on the served branch `feat/served`, one commit ahead of `main`.
3. The page shows the description, the discussion and the sidebar, and nothing about the commit the branch carries or the file it changes. See `screenshots/before.png`.

**Where it stops**

- `packages/web/app/pages/prs/[ref].vue` renders one column: description, Discussion, review form. No tab strip, no `?tab=` state.
- `packages/web/app/graphql/fragments.ts` `PrDetail` selects `revisions { head base date }` — the only thing the client knows about the branch is two SHAs.
- `packages/server/schema.graphql` `type Pr` has no field derived from those SHAs. `type Commit` exists, but only `Feature.commits` returns it (`packages/server/src/resolvers/feature.ts`).
- `packages/core/src/git/history.ts` has `mergeBase`, `isAncestor`, `searchCommits` (walks from HEAD, no range) and `commitMessages(cwd, range)` (messages only). The only `git diff` calls in core are `--cached --name-only` (`git/index-ops.ts`) and `--name-only --diff-filter=U` (`git/merge.ts`): nothing produces a patch, a name-status or a stat.

**What git costs, measured on a clone of go-gitea/gitea (git 2.55)**

| range | files | patch lines | `git diff -U3 -M` | `git log --reverse` |
|---|---|---|---|---|
| `v1.24.0..v1.24.3` | 136 | 5,065 | 65 ms | 10 ms (52 commits) |
| `v1.23.0..v1.23.8` | 362 | 16,430 | 128 ms | 13 ms |
| `v1.23.0..v1.24.0` | 2,813 | 289,069 | 694 ms | 26 ms (703 commits) |

So git is not the bottleneck for the 5 kLoC target; transport and the browser's DOM work are. Rename detection (`-M`) costs nothing measurable at these sizes.

**Plan**

- core: `commitsBetween(base, head)` and a `diffBetween(base, head)` that parses git's unified output into one record per file (path, old path, status, additions, deletions, binary, hunks). `base` is the pinned merge base, so `git diff base head` is the same three-dot diff a forge shows and stays right after the target moves.
- server: `Pr.commits` and `Pr.changes` field resolvers over the latest revision, cached process-wide by `base..head` (two SHAs name an immutable answer, so nothing invalidates it), with a line budget above which a file's patch is withheld and fetched on demand by path.
- web: a tab strip kept in `?tab=`, the commits and changes queries issued only when their tab is open, a diff view that parses hunks in the browser, renders plain rows (no per-line component), uses `content-visibility` so offscreen files cost no layout, and collapses files above a per-file threshold behind a "load" button.
