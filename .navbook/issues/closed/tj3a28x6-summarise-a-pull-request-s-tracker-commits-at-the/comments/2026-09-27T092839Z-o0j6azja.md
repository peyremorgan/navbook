## Plan

The browser must not learn the format (spec 05 §5.2, 06 §6.3), so the classification lives in core and the server sends it ready to render.

**1. Core: `packages/core/src/git/activity.ts` (new).** `trackerActivityAsync(cwd, navDir, base, head)`:

- One walk lists the commits that touch the tracker: `git log --reverse --no-merges -z --name-status --format=… base..head -- <navDir>`. The format and the separators follow `history.ts`.
- For each commit, `diffBetweenAsync(cwd, sha^, sha, { paths: [navDir] })` gives its tracker files. That runs once per commit, and a PR holds a handful of them.
- `summarise(commit, files, read)` returns `{ verb, kind, id, title, facts }`:
  - The subject is parsed against `docsSubject`'s grammar (`packages/core/src/core/ops.ts:88`) and the older `nb: <verb> #<id>`.
  - Paths are classified the way `tree.ts` `classify` does: `issues|prs/<status>/<id>-<slug>/…`, with an optional `archive/<year>/` prefix.
  - The main file's frontmatter is read at `sha^` and `sha` (`git show`, `parseFile`) and the keys are compared.
- It is a pure function over its inputs, so the tests can feed it made-up files.

**2. Server.**

- `RevisionCache.activityOf(base, head)` is kept per pair, like `commitsOf`, because the range is immutable.
- In `schema.graphql`, on `Pr`: `activity(limit: Int! = 100): TrackerActivity!`, with
  - `TrackerActivity { total, commits: [TrackerCommit!]! }`
  - `TrackerCommit { sha, subject, author, date, verb: String, kind, entity: String, title: String, self: Boolean!, facts: [TrackerFact!]!, files: [ChangedFile!]! }`
  - `TrackerFact { field: String!, before: String, after: String }`
- `ChangedFile.tracker: Boolean!`, so the client splits the net diff without knowing where `.navbook/` is. `ordered` already knows (`navDir`).
- Codegen is regenerated in `packages/server` and `packages/web`.

**3. Web.**

- `DiffView.vue`: the summary, file list, progressive rendering and "withheld" count read `files.filter(f => !f.tracker)`.
- The page's tab badge counts code files.
- `TrackerActivity.vue` (new) at the bottom: a `UButton` header with `aria-expanded`, collapsed by default. It fetches `PR_ACTIVITY_QUERY` when the tab opens, since the header needs the count. Each entry uses `DiffFile` for its files.
- The last line links to the Conversation tab through `<NuxtLink :to="{ query: {…rest} }">`, which is the same address the tab button writes.

**4. Tests.**

- Core unit tests for `summarise`: each verb, a hand-written subject, a move, the fact comparisons.
- A server test on a small repo built in the test.
- Web vitest for `TrackerActivity`.
- Playwright: see below.

## Acceptance

In the e2e fixture (`packages/web/script/fixture-repo.ts`), `feat/unserved` (`bbbb0002`) gains a tracker commit before its revision is pinned: a comment on `aaaa0001` (`docs(issue): comment on …`). Nothing reads that branch's issues, so no other spec moves. Then:

1. Open `/prs/bbbb0002?tab=changes`. The summary still says "2 files changed", and no `.navbook/` file is rendered among the diffs.
2. The "Navbook activity" header is at the bottom and says 1 commit. It is collapsed (`aria-expanded="false"`), and the timeline isn't in the DOM.
3. Click it. The entry reads `comment` + "Commented on issue …" with its SHA.
4. "Show diff" renders the comment file through `DiffFile`.
5. Click "Conversation tab". The address loses `?tab=changes` and the conversation is shown.
6. `bbbb0001`, whose range has no tracker commit, shows no activity section at all.

By hand, on this repository: `nav-server` on a clone at `dev`, then #rw1mjrnv's Changes tab shows 6 files (+280 −22) and two entries, "close #ozzaoa36 as fixed" (resolution — → fixed, open → closed) and "open this pull request".
