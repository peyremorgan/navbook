- **The cut.** The title column shrinks to its `minWidth` of 20. `slice(0, 19)` takes 9 emoji and the high half of a 10th. The bytes before the tilde are `f0 9f 98 80 ef bf bd 7e`: Node's stdout encoder replaced the lone surrogate with U+FFFD.
- **The width.** The CJK row is 20 "columns" by code point and 39 on screen, so it pushes `バグ` 19 columns right. The widest line is 54 columns (`wc -L`) in a 44-column terminal, so the terminal wraps it.
- **Wider terminals.** The alignment half shows without any cut. At 60 columns nothing is truncated, but the emoji title (31 code points, 56 columns) and the CJK row both run past the terminal's edge.

### Two corrections to the report

1. **The stdout bytes are valid UTF-8.** Node encodes a lone surrogate as U+FFFD (`EF BF BD`) on write, and `iconv -f utf-8 -t utf-8` accepts the captured output. The damage is a replacement character in place of the emoji, not a malformed stream. `truncate`'s *return value* is still ill-formed (`Buffer.from(cut).toString() !== cut`), so the proposed unit test is still the right assertion.
2. **Piping to a file never truncates.** `terminalWidth` (`packages/cli/src/commands/entity.ts:171-174`) reads `ctx.stdout.columns`, which is undefined without a TTY, so `renderTable` gets no width and never calls `truncate`. `nav issue list > out.txt` is intact. Only the padding half affects piped output.

### Where the code sits

- `renderTable` → `shrinkToFit` → `truncate`/`pad`: `packages/cli/src/render/table.ts:23-93`. The width computation at line 30 also uses `displayWidth`, so fixing the measure fixes it too. Headers use `.length`, which is fine: they are ASCII.
- Callers: `packages/cli/src/commands/entity.ts:168` (issue/pr list) and `packages/cli/src/commands/feature.ts` (feature list).
- The fix needs no network. `string-width@8.2.2`, `get-east-asian-width@1.6.0` and `strip-ansi@7.2.0` are already in the pnpm store as transitive dependencies of other packages.
