## Confirmed

Reproduced on `dev` at `6cf8d86` (git 2.55.0, `/bin/sh` → bash 5.3.15), running this checkout's CLI through a `nav` shim on `PATH`, since the hook calls `nav` by name.

Culprit, `packages/cli/src/install/hook.ts:32-37`:

```sh
if command -v nav >/dev/null 2>&1; then
  nav doctor --staged          # under set -e the hook ends here on any non-zero exit
  if [ $? -eq 2 ]; then
    exit 1
  fi
fi
```

### Matrix

Three ways to break the tree, crossed with three kinds of pre-existing hook. The "none" hook is the one `nav install` writes itself when no hook exists.

| `doctor --staged` | Existing hook | Commit | Correct? |
|---|---|---|---|
| exit 1: `.navbook/` removed | `set -e` | **refused** | no |
| exit 1: `.navbook/` removed | plain | made | yes |
| exit 1: `.navbook/` removed | none | made | yes |
| exit 1: `NAV_ROOT=does-not-exist`, tree intact | `set -e` | **refused** | no |
| exit 2: an `issue.md` with no frontmatter | `set -e` | refused | yes |
| exit 2: an `issue.md` with no frontmatter | plain | refused | yes |
| exit 2: an `issue.md` with no frontmatter | none | refused | yes |

The `NAV_ROOT` row matters most. Nothing is wrong with the repository, but an exported variable in one shell stops every commit in it. All git shows the user is nav's own diagnostic:

```
existing
nav: not a Navbook repository: no .navbook/ at the repository root
run 'nav init' to create it
```

The exit-2 rows show the block's intended behaviour already works. A fix has to keep them as they are.

### Repro script

The script in the issue body writes the hook with `printf '%s'`, which prints the `\n` escapes as literal characters. The "hook" it creates is then one line, `#!/bin/sh\nset -e\necho existing\n`, and its shebang is broken. `'%b'` interprets the escapes:

```sh
# repro.sh <dir> <hook-prefix> <missing|malformed>
D=$1; PREFIX=$2; BREAK=$3
rm -rf "$D"; git init -q -b main "$D"; cd "$D" || exit
git config user.name T; git config user.email t@example.com
printf '%b' "$PREFIX" > .git/hooks/pre-commit; chmod +x .git/hooks/pre-commit
nav init --commit >/dev/null
nav install --hooks -y >/dev/null
case $BREAK in
  missing)   git rm -r -q --cached .navbook; rm -rf .navbook ;;
  malformed) nav issue open "x" -m "y" >/dev/null
             f=$(ls .navbook/issues/open/*/issue.md); printf 'no frontmatter\n' > "$f"; git add "$f" ;;
esac
( nav doctor --staged >/dev/null 2>&1; echo "doctor --staged exit=$?" )
echo x > file.txt; git add file.txt
git commit -q -m "add a file" 2>&1; echo "commit exit=$?  head=$(git log -1 --format=%s)"
```

```
$ repro.sh a '#!/bin/sh\nset -e\necho existing\n' missing
doctor --staged exit=1
commit exit=1  head=docs: initialize navbook
$ repro.sh b '#!/bin/sh\necho existing\n' missing
doctor --staged exit=1
commit exit=0  head=add a file
```

### Test gap

`packages/cli/test/cli/install.test.ts` checks the block's text when it is appended and when it is removed. No test runs the resulting hook, so the suite passes against the bug.
