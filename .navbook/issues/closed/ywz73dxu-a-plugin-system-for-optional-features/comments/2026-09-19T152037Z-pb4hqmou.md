All seven phases have landed. The knowledge base is a plugin (42fab43), which was the acceptance test for the whole design.

Core lost 911 lines and knows what a feature is nowhere. The CLI lost its `feature` command tree, the server lost four mutations and two types, and the format lost nothing: `specs/` and `feature:` are still spec 02 §2.11's, grandfathered by §2.12, and D13 and D14 keep their numbers so one conformance suite still validates an implementation with features built in and one with them in a plugin.

The extraction found four real faults rather than just moving code: a plugin's root GraphQL query needs `sync.read` rather than the locked memo or it answers from a stale clone; the plugin was importing `@navbook/core` at runtime, which resolves in the workspace by accident and fails in a real store; `nav plugin install <tarball>` looked for the package under the path it was given rather than the name npm resolved; and short flags were refused for every plugin option, which would have cost `nav feature open -m`. Each is fixed and covered.

Two seams were added because nothing existed: `entityInput` on the server host, which carries a plugin's own input fields onto the frontmatter and into the query, and argument completers, which the manifest declared and nothing invoked. Everything else the plugin needed was already there.
