Confirmed on `dev` at 4bc9c83, against `@nuxt/ui` 4.11.0 and `@nuxtjs/color-mode` 4.0.1.

## Repro

In a browser:

1. With nothing stored for the app's origin, set the system to dark and open the app: it is dark.
2. Press the navbar theme button twice. The page looks as it did, but `localStorage.getItem('nuxt-color-mode')` is now `"dark"`.
3. Switch the system to light. The page stays dark, and stays dark across a reload. Nothing on the page restores `system`.

No browser was available in the sandbox, so I checked it by running the head script from the built `packages/web/.output/public/index.html` under Node, with a fake `matchMedia` and localStorage:

```
OS prefers dark   stored null    ->  <html class="dark">
OS prefers light  stored null    ->  <html class="light">
OS prefers dark   stored system  ->  <html class="dark">
OS prefers dark   stored light   ->  <html class="light">   <- after a press
OS prefers light  stored dark    ->  <html class="dark">
```

## Where it happens

- The head script only asks `prefers-color-scheme` when the stored preference is missing or `system`:

  ```js
  s = getStorageValue("localStorage", "nuxt-color-mode") || "system";
  let r = s === "system" ? f() : s;
  ```

  The client plugin (`@nuxtjs/color-mode/dist/runtime/plugin.client.js`) also listens for system changes only while `colorMode.preference === "system"`, and writes every preference change to storage.

- `UColorModeButton` (`packages/web/app/layouts/default.vue`, the `theme-toggle` test ID) can only set two values:

  ```js
  set(_isDark) { colorMode.preference = _isDark ? "dark" : "light"; }
  ```

  So a press can never write `system` back.

- `packages/web/test-e2e/theme.spec.ts` has "goes back to light when the button is pressed again". It runs in a browser that prefers light, so it can't tell a pinned `light` from `system`, and it passes with this bug in place.

## For the fix

- Nuxt UI already ships `UColorModeSelect`, a menu of System / Light / Dark bound to `colorMode.preference`. It is wide for the navbar next to the inbox menu, though.
- Another way that fits the navbar: keep an icon button that steps through `system -> light -> dark -> system`. Give it an icon for each preference and an `aria-label` that names both the current preference and where the next press goes.
- The e2e spec should cover returning to `system` from a browser that prefers **dark** after choosing light, so that pinned and followed look different. It should also check that `system` holds across a reload.
