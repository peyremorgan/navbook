Self-review at high effort, against revision 2.

I read every hunk and then checked the things reading cannot settle. The unit suite runs (11/11 on `title.test.ts`, 330/330 for the package), `nuxi typecheck`, `tsc -p tsconfig.tools.json` and `biome check` are all clean. I confirmed the end-to-end assertions match the fixture rather than my memory of it — `aaaa0001` and `bbbb0001` are the fixture's parent issue and served pull request, `authentication` is titled "Authentication", `specFileName("Login flow")` is `login-flow.md`, and no earlier spec renames any of them. The suite is `workers: 1, fullyParallel: false`, so sharing the one stack is safe in the order the specs run. All thirteen routes are accounted for: `app/pages/index.vue` is a `definePageMeta({ redirect })` stub that never renders, so having no title is right rather than missed.

It found two things, both now fixed in 398d974.

**The fallbacks were guarded with `??`, which does not catch what the server actually sends.** `core`'s `tree.ts` reads a missing or non-string frontmatter `title` as `""` (three places, lines 418, 429 and 515) rather than omitting the field — read-time `requireString` problems are raised on write and never filter a query's answer. So a feature or a specification document with no usable title reached `pageTitle("")` and rendered the bare `Navbook`, which is precisely the bug this branch exists to fix, on precisely the entity least likely to be noticed. The slug and the file name are both in the address and were known the whole time. `||` reaches the fallback that was meant.

**The end-to-end spec's most important assertion could not fail.** It captured `await signedIn.title()` immediately after `goto` to compare against later. `goto` resolves on load and the app mounts after it — `app/plugins/01.config.ts` fetches `config.json` before the first route renders — so what it captured was the shell's `Navbook`, not `Issues · Navbook`. The closing `not.toHaveTitle(listing)` would therefore have passed even if in-app router navigation stopped retitling the page, which is the one regression that test is there to catch. It now waits for the listing's own title before capturing it.

Neither was blocking and nothing else came up: the route-param shapes, `shortId` on a full id, a whole directory name and a four-character prefix, and the null-versus-loading branch on both detail pages are all correct.

**Approving with one gap stated rather than buried.** `test-e2e/titles.spec.ts` has still never been executed — Playwright's Chromium cannot be downloaded in this environment — so the e2e finding above came from reading it, and the fix to it is unverified by a run. What stands in for a browser is the built artefact: `nuxi generate` emits all twelve `useHead` call sites into the chunks, eight literal and four in the reactive `computed` form, with both separators present. That proves the titles ship, not that they render. `pnpm --filter @navbook/web test:e2e` is worth a run on a machine that has the browser.
