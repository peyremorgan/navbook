Self-review, re-read against the provider and library sources rather than the PR description.

**Checked, and fine**

- **The authorize URL now carries `resource` as well as `audience`.** Better Auth 1.5.6 validates `/oauth2/authorize` with a plain `z.object` (no `.strict()`), so it drops keys it doesn't know. That is why the existing `audience` never broke sign-in, and `resource` is dropped the same way. On the token endpoint, `resource: z.string().optional()` matches the single string we send.
- **Refresh.** `handleRefreshTokenGrant` goes through `checkResource`, which only checks the value against `validAudiences`. Nothing requires it to match the original grant, so sending the same audience on every refresh is correct.
- **`ApiUserManager.signinSilent`** spreads `args` after the default, so an explicit `resource` from a caller still wins. The iframe fallback path also accepts `resource`, so defaulting it there is harmless. `$oidc` is still typed as `UserManager`, and the subclass satisfies that.
- **Moving settings into `app/utils/oidc.ts`.** The settings match the old plugin's, plus the two `resource` entries. `userStore` stays in the plugin because it needs `window.sessionStorage`.
- **Dev issuer.** On refresh, the rotated session keeps whichever audience the refresh named, and a request without `resource` falls back exactly as before. The existing tests still pass.
- **Tests.** The refresh assertion was mutation-checked: without the override it gets `null`.

**Notes, not blocking**

- `app/utils/*` is auto-imported by Nuxt, so `ApiUserManager` and `oidcSettings` become globally available names. That's harmless, but the plugin still imports them explicitly for readability.
- The Playwright suite was not run (no room in `/tmp`). The unit test covers the parameters on all three token requests, which is the part that regressed.
