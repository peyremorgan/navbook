Self-review of the diff against `dev`, file by file, with the runner read for its failure modes.

**Changed during review.** `gitRunAsync` stopped an overflowing command with `SIGKILL`, while a timed-out one gets `SIGTERM` first. `spawnSync` sends `SIGTERM` by default, and it is what lets git remove its lock files, so the overflow path now goes through the same stop and settles on `exit` like the timeout does. Recorded as revision 2.

**Checked and holding.**
- The two runners share the environment, the buffer default and the spawn-failure message, so `gitRun` and `gitRunAsync` cannot disagree about what "git is missing" looks like.
- Every `…Async` twin shares its arguments and its reading of git's output with the blocking form through one helper, so there is no second definition of a fast-forward, a conflict, a branch name or a SHA.
- `RepoSync` keeps the exact call order the matrix pins down: the fakes went async and every existing assertion passed unchanged before any new one was added.
- A stopped fetch is reported with `keptLocalCommit: false`, a stopped push with `true`, and a stopped push is not retried, since retrying would only wait the timeout out again.
- A `GitError` from a network call is still passed through to `translate()` and reaches the client as `GIT_ERROR`, as before.
- `lastFetch` moves only after a fetch that returned, so a stopped fetch does not extend the staleness window.
- `settle()` runs once; a late `close` after a timeout, or a spawn `error` followed by `close`, cannot resolve a promise that was already rejected.
- The `killer` timer is only ever created once and is cleared on settle, so nothing outlives the call.

**Known and deliberate, not blocking.**
- While a remote is down, each read that needs a fetch waits the full timeout before failing, and they do so one after another under the lock. Serving the stale tree on a failed fetch, or backing off after one, would be a behaviour change beyond this ticket; worth its own issue if it bites.
- The responsiveness test's `< 1500 ms` bound against a 3 s stall can pass for the wrong reason on a machine slow enough that the probes land before the push starts, but cannot fail short of the process itself stalling.

Approving: biome, `tsc` for every package, and the core, server and deploy suites pass on revision 2.
