I ran an adversarial self-review (`/code-review high`) on revision 1. It raised eight findings: two were real bugs, now fixed in `0262d34`, and six I left as they are, for the reasons below. Revision 2 is rebased onto `dev` at `6052586`.

## Fixed

1. **A huge count still produced the original symptom.** `--commits 3000000000` passed the parser, but git reads `-n` as a C `int` and refuses anything larger outright, so `searchCommits` answered `[]` and the command printed `recent commits (0)` with exit 0. `searchCommits` now leaves out `-n` when the limit is past `2^31 - 1`, because a limit that large is effectively no limit. There is a new assertion in `core/test/feature-ops.test.ts` for this, and it fails without the change. There is also a CLI case.
2. **`Number` accepts hex, binary and exponent spellings.** `--depth 0x10` rendered 16 levels, `--rank 0x1A` stored 26, and `nav id -n 1e12` passed the parser and started minting a trillion IDs (`parseInt` used to read that as 1). Both parsers now accept plain decimal notation only, and a count must also be a safe integer. The refusal tests now include `0x10`, `1e1`, `0x1A`, `1e3` and `2^53 + 1`.

## Left as they are

- **`searchCommits` swallows every git failure as `[]`.** This is the root cause, and it's real, but it's a behaviour change for every caller (an unborn branch is one place where git exits non-zero legitimately), so it's out of scope here. Fix 1 closes the one route a flag had into it.
- **`cmdShow` and `cmdIssueOpen` lost their own guards.** That was deliberate, per the plan: `program.ts` is their only caller. `mintIds` keeps its check because it is exported from core.
- **Commander's `error:` format instead of `nav:`.** This was decided in the plan (§4) and is noted in the PR description as a release-note item.
- **`Number.isInteger` on a GraphQL `Int!` is dead code, and the check duplicates `Pr.commits`'s.** I kept both so the two `commits` fields read the same. A shared helper is a reasonable follow-up.

After the fixes, all suites pass: core 814/814, CLI 379/379, server 378/378 and conformance 119/119, with `biome` and `tsc` clean. `nav doctor` shows no errors and one warning, which is already on `dev` (#tvxw30h3 references a PR on another branch).
