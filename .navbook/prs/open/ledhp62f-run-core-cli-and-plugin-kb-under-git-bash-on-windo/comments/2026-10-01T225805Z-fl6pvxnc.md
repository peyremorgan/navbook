## Blocking

**Lint, fixed.** The import order in `remote.test.ts` was my mistake: I put `./helpers/platform.ts` between two `../src/git` imports. The two `String.raw` wrappers with no escapes in them are gone. `biome check .` now reports only `TestStateBadge.vue`, which #fkjna1iy fixes. `pnpm typecheck` is clean.

## Worth fixing

**`hermetic.ts` is not hermetic: fixed.** It pins `GIT_CONFIG_GLOBAL=/dev/null` too, which Git for Windows accepts as `GIT_CONFIG_SYSTEM` already shows in `deterministicEnv`. Core still passes in full under it (923 pass, 10 skipped), so no core test was leaning on a developer's identity. The comment now names both files.

**The preload is only on `core`: a stated principle now, not a second mechanism.** `cli`, `plugin-kb` and `plugin-tests` run git through `TempRepo`. Its `deterministicEnv` already sets `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_SYSTEM` for every command, which is why only core needed one. `hermetic.ts` says so. A preload in those packages would pin the same two variables a second way.

**`fileVersions` unverified outside this machine: fixed, and the truncation point was right.** The record-reading loop is now a pure, exported `readFollowLog`. Five tests feed it synthetic `git log` output, so they hold on any git:

- the pre-2.56 shape;
- the 2.56 shape;
- a rename;
- a copy;
- nameless merge records.

You were right that a listed merge with no name-status fields resolved to the *requested* path. After a real rename that is the wrong path, and it would have cut the history short. Such a record now keeps the path the history has reached, so an ordinary merge can never trip the hidden-rename check.

**`hasScheme`/`looksLocal` untested: fixed.** Both are exported, and `looksLocal` takes a `platform` and uses `path.win32` or `path.posix` accordingly. `spawning.test.ts` pins both on every platform. That covers drive letters both ways, UNC paths, `/…` on both, and `github:a/b` and `git+ssh:` as URLs.

**`taskkill` has no timeout: fixed.** `killTree` resolves at the same deadline a POSIX group stop allows (grace plus reap), whatever `taskkill` does. The SIGKILL grace timer is no longer scheduled for a Windows group, so the dead code is gone too.

**`NO_GIT_SHIM` disproved by `npm.cmd`: I disagree, with evidence.** `npm.cmd` works because `npmInvocation` hands it to `cmd.exe` explicitly. Code that spawns `git` gets no such help. Node's Windows path search tries only `.com` and `.exe`, and it refuses to spawn a `.cmd` without a shell. I checked on this machine:

- With a `git.cmd` printing `SHIM` first on `PATH`, `spawnSync("git", ["--version"])` answered `git version 2.56.0.windows.1`, the real git.
- `spawnSync("git.cmd", …)` failed with `EINVAL`.

So a batch shim is never the git the code under test runs. Recovering those five tests would need a stand-in compiled to an `.exe`. That is possible, but it is a fixture project of its own, and I have left it out of this PR.

**`killTree`'s reach asserted nowhere: fixed, better than skipping.** The helper's shell is git's own child, still parented to it. It now writes its pid (the Windows one, through `/proc/$$/winpid`), and `assertReached` asserts it is gone on every platform. Only the backgrounded `sleep`, which Git Bash's fork emulation orphans, keeps the Windows exception. That passes here, so the tree kill reaching git's children is now asserted where it runs.

**No Windows CI job: added.** `test-windows` runs on `windows-latest` under Git Bash:

- pnpm's `script-shell` is set to Git Bash, as the README describes;
- it runs `core`, `cli`, `plugin-kb` and `plugin-tests` one package at a time;
- it then runs the conformance suite.

One at a time because several suites bound how long a stop may take, and a shared runner misses those bounds. I ran that exact command locally before merging. The job itself has not run on GitHub yet; its first run is on this merge.

## Found while verifying these fixes

**A stopped push could still land on Windows.** `remote.test.ts` "stops a push the remote sits on" failed twice under load. The second push was refused because the remote's `main` had moved: the push the test had timed out landed after all. A push with a timeout but no signal runs without a process group. So the stop ended `git push` alone, and on Windows its `receive-pack` lived on and completed once the hook unstalled. On POSIX it dies with its parent.

On Windows a stop now always ends the tree, with or without `processGroup`. Windows has no gentler stop to preserve. The call answers once the tree kill has run, bounded by the deadline above. The test without a group now states each platform's behaviour:

- POSIX: the helper is left running, as before.
- Windows: git's child shell is gone.

Relatedly, the pid snippets read `/proc/<pid>/winpid` with the `read` builtin instead of `cat`. A process start costs a Windows shell enough to lose a 300 ms race under load.

## Minor

- **`cmd.exe` hardcoded: fixed.** It now uses `%ComSpec%`, falling back to `cmd.exe`, as cross-spawn does. The interpreter is a parameter, so the test still pins exact output, and there is a case for an explicit `ComSpec`.
- **`posixShell` degrades silently: fixed.** When the shell beside git is not there, as with an MSYS2 git reporting `/mingw64/libexec/git-core`, it searches `PATH` for `sh.exe` before falling back to `cmd.exe`.
- **Duplicated helpers: fixed.** Core exports its platform helpers as `@navbook/core/test-helpers`, a workspace-only export like cli's and server's. `@navbook/cli/test-helpers` re-exports `NO_SYMLINKS`, `NO_GIT_SHIM` and `NO_PROCESS_GROUPS` from it, and `TempRepo.record` calls core's `recordInIndex`. `editInPlace`, which `links.test.ts` had to itself, moved there too, for the `sed` fix below.
- **`.gitattributes` carve-out: fixed.** It adds `*.bat text eol=crlf`. It also says why `.ps1` needs no line: PowerShell reads LF scripts as they are.
- **The single-letter scheme change belongs in the PR body.** Noted here, since a merged description is history. A one-letter scheme is no longer read as a URL: `x:foo` is a package spec, and `C:\…` is a path. No scheme npm reads has one letter.

## Pre-existing

**BSD `sed` in `plugin-tests`: fixed while here.** The editor used `sed -i`, which BSD reads differently. It now uses `editInPlace` (sed to a scratch file, then `mv`), the same helper `links.test.ts` already used for exactly this reason. The README's Platforms section now says all four suites pass under Git Bash and that CI runs them there.
