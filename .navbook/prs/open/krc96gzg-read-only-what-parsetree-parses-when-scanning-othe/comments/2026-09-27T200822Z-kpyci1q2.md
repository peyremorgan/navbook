Self-review of revision 2, head `ee8beaf`. Ran `/code-review high` on the branch and fixed everything it found in `ee8beaf`.

**Fixed**
- **One buffer for every ref, and repeated reads.** Revision 1 put every ref's blobs into one `cat-file` batch with a shared 256 MB limit, and deduplicated by whole `prs/open` tree. So a PR directory carried by branches whose `prs/open` differ (every branch that opened its own PR) was read and parsed once per tree. The scan now:
  - lists each distinct `prs/open` with `ls-tree -r -t -l`;
  - parses each version of a PR directory (keyed by name and subtree SHA) once;
  - reads blobs by SHA, each once, in batches split by their listed sizes (`readBlobsBySha`, 64 MB per batch).

  Test: a second branch with its own PR carries this one's directory unchanged, and its `pr.md` SHA is requested exactly once. That test fails on revision 1.
- **Silent loss that remained.** The recursive `ls-tree` went through `gitMaybe`, so a failure read as an empty directory. A requested blob that came back `missing` was also filtered out of the keys, and the PR was dropped. Both now throw: `lsTreeEntries` uses `git()`, and `readBlobsBySha` names the missing objects. The test deletes the loose `pr.md` blob, then the PR's subtree object, and expects an error. It fails on revision 1.
- **A best-effort hint failing the command.** `countOpenPrsOnOtherRefs` now throws on an unreadable ref, and `nav pr list` calls it for its stderr hint *after* printing the table. The hint now catches and says nothing. A CLI test with a failing `cat-file` shim checks that exit 0 and an empty stderr are kept.
- **Found while fixing the rest: EPIPE hides git's message.** If git exits before reading all of its stdin, `spawnSync` reports `EPIPE` rather than the exit. The full-suite run hit this as a flaky failure. `gitRun` and the scan's `cat-file` now report the exit status and stderr as a `GitError` (`exitedEarly`). A deterministic test uses 200 KB of input against a git that exits at once.
- **Cleanups.** `spawnFailure` names the command and the byte limit on `ENOBUFS` for every synchronous runner. The unused `lsTreeNames` and `lsTreeRecursive` are removed. The misleading buffer comment is rewritten.

**Deliberately kept**
- `parsedPaths` and `parseTree` both run `classify`, so it runs twice per distinct PR directory. That keeps one reader of the directory grammar, and it is string splitting on a handful of paths.

**Follow-up, not in this PR**
- The `doctor --staged` fix (#d8oflfva, now on `dev`) added its own `catObjects` in `git/index-ops.ts`. It does the same SHA-keyed read as `readBlobsBySha`, sizes its buffer rather than batching, and still does `throw result.error`, so it has the EPIPE problem above. The two could share one reader.
