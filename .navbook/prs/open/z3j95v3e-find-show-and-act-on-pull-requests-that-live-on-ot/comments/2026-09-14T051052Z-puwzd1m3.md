Request changes. I found the following issues:

1. **Severity: Blocker — detached HEAD writes remain possible.**
   **Location:** `packages/cli/src/commands/pr.ts:164` and the shared commit/write path.
   **Explanation:** `findPrToWrite` verifies that the PR exists in the current tree, but does not reject a detached HEAD. Commands such as `nav pr review ... --commit` can therefore write and commit review data on a detached commit, making the result unreachable from any branch. This is especially important because the PR includes the detached-head issue as a stated concern.
   **Recommended change:** Add a shared detached-HEAD precondition before any PR write or commit, and provide an actionable message to switch to the relevant branch/worktree. Add a regression test for `review --commit` from a detached HEAD.

2. **Severity: Major — the empty-list hint can disagree with `--all-refs`.**
   **Location:** `packages/core/src/ops/pr.ts:488-530`, especially `countOpenPrsOnOtherRefs`.
   **Explanation:** `listPrsAcrossRefs` filters settled PRs using the PR target branch plus the default branch via `dropSettledOnTarget`, but the hint count removes settled IDs only from the default branch. If a PR target branch records it as merged/closed while the default branch does not, the normal list can be empty while the hint incorrectly says that an open PR exists elsewhere.
   **Recommended change:** Reuse the same target/default settlement calculation in the count path, or factor the settlement filtering into a shared helper used by both listing and hint counting. Add a test where the target branch is settled but the default branch is not.

3. **Severity: Major — detached HEAD causes false “other branch” counts.**
   **Location:** `packages/core/src/ops/pr.ts:488-530`, classification by `ref.short === here`.
   **Explanation:** `currentBranch()` returns `null` for detached HEAD. As a result, every ref carrying the PR, including the commit currently checked out, is classified as elsewhere, so the hint may claim that another branch holds a PR that is actually present in the current tree.
   **Recommended change:** Detect the current checked-out tree/commit (or resolve the detached HEAD to its containing branch/ref where appropriate) before classifying refs; ensure a PR present in the current tree is excluded from the “other refs” count. Add detached-head coverage.

4. **Severity: Minor — review summary can discard an earlier opinionated verdict.**
   **Location:** `packages/core/src/ops/pr.ts:767`.
   **Explanation:** Selecting the latest verdict of any kind per reviewer means a later `verdict: comment` replaces an earlier `approve` or `request-changes`. The documented behavior requires the last opinionated verdict, falling back to `commented` only when no opinionated verdict exists.
   **Recommended change:** Select the latest opinionated verdict independently, and use a comment verdict only when that reviewer has no opinionated verdict. Add a regression test for approve followed by comment.

The implementation is otherwise reasonably scoped, and the CLI test suite passes, but these correctness issues should be addressed before approval.
