Thanks. Three of the four were real and are fixed. The fourth does not apply. The fixes are recorded as a new revision at `87fa168`.

1. **Detached HEAD writes: fixed in `7e23aa8`.** This predates the PR and is tracked as #mdftn010, but it belongs here. `--commit` now refuses on a detached HEAD in `assertCommittable`, which `runPlan`, the link and the delete planners all go through, before any file is written. It applies to issues as much as to pull requests. When a branch points at HEAD, the refusal names it, and the worktree that has it checked out if there is one. Without `--commit`, writing and staging still work, since nothing is lost until someone commits. Tests cover `pr review --commit` detached at a branch held by another worktree, detached at a branch no worktree holds, `issue open --commit` detached at a commit no branch points at, the no-`--commit` case, and `planEntityDelete` in core.

2. **Hint disagreeing with `--all-refs`: fixed in `87fa168`.** Confirmed with a pull request targeting `dev` and merged there, seen from `main`: `--all-refs` listed nothing and the hint said "1 open pull request". The count now reads each candidate's `target` from its `pr.md` (one blob per distinct tree, so it stays cheap) and settles it through `settledOnTargets`, the helper `dropSettledOnTarget` now shares. Regression test added.

3. **Detached HEAD in the count: fixed in `87fa168`.** The count now decides what the checkout already holds from `HEAD:<navDir>/prs/open` instead of the branch name, which gives the same answer on a branch. Regression test: detached at `feat/auth` with a query that matches nothing, no hint.

4. **Comment verdict discarding an earlier opinion: does not apply.** `reviewSummary` does not take the latest verdict of any kind. For each comment it calls `nextState` (`packages/core/src/core/review.ts`), which returns `undefined` for a `comment` verdict when the person already stands at `approve` or `request-changes`. The opinion stands, and only a later opinionated verdict replaces it, as spec 02 §2.7 says. Two existing tests pin this in `packages/core/test/review.test.ts`: "does not let a comment verdict retract an opinion its author already gave" and, the other way round, "upgrades a comment verdict when its author later takes a side". The cited `pr.ts:767` at `512f9f7` is `conflictStop`, and this PR does not change `review.ts`.
