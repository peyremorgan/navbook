Self-review. The matching itself holds up — anchored prefix of `<id>-<slug>`, a
floor of four, the `#` stripped, ANDed like any other term — and the tests pin
each of those. What is wrong is everything around it that still describes the
old behaviour, which this PR set out to update and did not finish.

1. **The API documents the old rule.** `packages/server/schema.graphql:394`
   says `EntityFilter.text` is "Free text, matched against title, body and
   comments." That is what GraphiQL shows, and it is copied into
   `packages/server/src/generated/resolver-types.ts` and
   `packages/web/src/generated/gql/graphql.ts`, so the schema needs editing and
   both codegens rerunning.

2. **The inbox's empty state is now wrong.** `packages/web/app/pages/inbox.vue:116`
   says nothing of yours "has those words in its title, body or comments". The
   inbox searches through the same server path, so it gained the ID match too;
   the sentence should say so.

3. **The README's example is a trap in a shell.** It is in the CLI's query
   section and suggests `#ywz73dxu` — unquoted, bash and zsh read `#` as the
   start of a comment, so `nav issue list #ywz73dxu` silently lists everything
   open. It also uses live IDs from this tracker where the README has its own
   running example, `bqlybac0`. Use that, and show the `#` form quoted.

4. The description is missing the "Generated with Claude Code" footer.

None of these change behaviour; all of them are places where the project would
tell a reader something untrue.
