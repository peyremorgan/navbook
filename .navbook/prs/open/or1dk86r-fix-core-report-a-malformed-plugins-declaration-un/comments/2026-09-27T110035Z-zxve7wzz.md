Adversarial self-review (`/code-review high`). Nine findings: five are fixed in 6d65f5f, and four were rejected with reasons.

## Fixed

- **Shared fallback object.** Every fallback returned the shared `NO_PLUGINS` or a spread of it, and the spread kept its `plugins` object. So a caller adding to the declaration it was handed would declare that plugin for every later reading in the process, which matters most in the server. Each call now builds its own objects, and the constant is gone. A test mutates one reading and checks the next.
- **Inherited names.** The map inherited from `Object.prototype`, so `plugins.toString` and `"constructor" in plugins` answered for extensions nobody declared. It is now a null-prototype object, which also stores `__proto__` as an ordinary entry.
- **Empty key.** `""` was accepted as a name. §2.12 calls the key "an identifier a reader can look up", so it is now a D15 fault. There is no conformance fixture for it: that would hold a second implementation to my reading of the spec, rather than to something the spec says outright.
- **Ambiguous message.** `'plugins."a'b"'` was unclear. The entry message is now `'plugins' entry "<name>" must be an object`, with the name JSON-quoted outside the single quotes.
- **Untested reader.** `readPluginDeclaration` now has tests beside `readReviewPolicy`'s, covering a renamed root, no marker, and a marker that is not JSON.

## Not changed

- **"A bad entry should void the whole declaration."** §2.12 reads a malformed declaration "exactly as a malformed review policy is", and §2.10 says each review key "falls back to its default independently". So an entry falls back on its own to not being declared, and the good entries stay, as the issue's plan says.
- **Three `JSON.parse`s of the marker, the duplicated whole-file checks, and `checkMarker` collapsing messages by string.** All three are true, but they describe the pattern the two policy readers already follow, which this change mirrors on purpose. The marker is a few hundred bytes. Folding all three readers into one parse is a refactor for its own PR.
