Reviewed at `high` effort against revision 2, having written revision 1 — so read this as a second pass over my own work rather than as an independent one.

Several things that looked wrong turned out not to be, and are worth recording so the next reader does not re-derive them:

- **Double-click while a save is out.** `UButton` renders `:disabled="props.disabled || isLoading"`, so `:loading="props.save?.saving"` really does block a second toggle rather than merely dimming the first.
- **The button vanishing after a write.** `evictListings` drops `ROOT_QUERY.people` after every mutation, which would null `self` out if `usePeople` went briefly empty. It does not: Apollo's `getCurrentFullResult` overwrites `result.data` only on a complete cache diff, so the previous answer stands while the refetch is out.
- **The inbox.** Assigning under the repository's named spelling still matches a token carrying the bare address, because the server compares with `personMatches`/`sameEmail` rather than by string.
- **A refused or stale edit underneath.** Clicking the toggle against an overlaid refusal builds a null patch and settles it, which reads the same in both directions.

Two findings, both fixed in `b5b1237`:

**`togglePerson` removed one spelling and matched every one.** It found the person by address, then filtered by exact string — so a list that had come by both spellings of one address was half cleared, and the button went on offering to remove somebody it had just removed. Reachable without hand-editing anything: the menu takes free text, so typing a bare address beside a named entry is enough. `namesPerson` is now the primitive and `togglePerson` filters every entry it decides against.

**The end-to-end round trip proved nothing.** Every assertion was satisfied by the optimistic overlay, which says what was clicked before the server answers. The test ended there, aborting the request it never waited for, and would have passed whether or not anything reached the file — leaving the shared fixture dirty for whatever ran next, and green either way. Each half now reads back from a reloaded page, which is what the separate reload test had been for, so that one is gone.

Also corrected the description, which claimed 148 end-to-end tests all green. That number was never run: the suite is 145, and at the time I wrote it one of them was failing. It is 145 green now.
