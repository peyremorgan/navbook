Found and fixed in dae74f8:
- GIT_CONFIG_COUNT was read in base 0; git reads it in base 10 (`010` is ten entries, `0x2` refused). The misread could overwrite the caller's entries or refuse to start on a count git accepts. The tests now fill one more entry than the count names.
- The startup sweep's running-git guard only saw gits whose working directory was in the worktree. It missed a git in another worktree of the same repository, or one pointed at it with `--git-dir` or `GIT_DIR`, and would remove its lock. It now checks every worktree plus the git and object directories, and reads each process's environment and command line.
- `gitDirs` used `--path-format=absolute` (git 2.31 and later); it now resolves git's relative answer itself.
- A failed run with empty stderr is logged without a dangling colon.
