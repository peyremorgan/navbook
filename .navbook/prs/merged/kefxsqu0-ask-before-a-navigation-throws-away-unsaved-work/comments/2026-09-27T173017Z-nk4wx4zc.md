Adversarial self-review of revision 1 (`/code-review high`). Nine findings, all fixed in `449239e` and, after rebasing onto the plugin system and the provider sign-out, `0d39e61`:

1. **Drafts not held:** the knowledge base's "Add a document" and "New feature" dialogs. They are held now, while open and not empty.
2. **`beforeunload`'s legacy `returnValue` was `""`**, which older browsers ignore. It is a non-empty string now.
3. **FORBIDDEN with a dirty draft:** "Keep editing" reset `sendingAway`, so every later refusal asked again. The flag is now lowered only by a navigation that lands.
4. **UNAUTHENTICATED dropped the token before the browser prompt**, and asked again on every later operation. It now asks in the app before forgetting the token. "Stay" keeps page, draft and token, says the write failed, and does not ask again until the person moves.
5. **The guard ran after `auth.global`**, so a declined leave could still renew a token or redirect to the provider. It is now `middleware/00.unsaved.global.ts`, which sorts first.
6. **A same-path navigation during the question left a stale dialog** answering a cancelled navigation. Any new navigation now answers an open question with "stay".
7. **`discard()` released every hold for good**, so a failed sign-out left drafts unguarded. Replaced by a one-shot `agree()` spent by the next guard or unload.
8. **Refused edits kept by `usePendingEdits` / `useStaleEdit` were not held.** They are now, on the issue, PR and feature pages.
9. **`dirty()` copied the Set on every call.** It loops directly now.

Found while rebasing:

- **Leave question mid sign-out.** With #icroff4l's sign-out on dev, an operation in flight could come back UNAUTHENTICATED during `logout` and open the leave dialog mid sign-out. It is now ignored while `useAuth().signingOut()` holds, as `login` already did.
- **Plugin fields on `issues/new.vue`.** Each field's pre-fill (its first value pushed into `extra`) is now the baseline, so arriving from "File an issue" with `?feature=` is not a draft.
- **Tests moved to plugin-kb.** The document-editor and add-document cases now live in plugin-kb's e2e suite, since a host bundle built without the layer has no `/features`.

Evidence at revision 2, built with `NAVBOOK_WEB_PLUGINS=@navbook/plugin-kb` as in CI:

- **E2E:** full suite 169/169, including the 14 unsaved-work cases (10 host, 4 plugin-kb). The self-review's 4 new cases failed against revision 1.
- **Unit tests:** web `vitest` 410/410, plugin-kb 138/138.
- **Static checks:** `nuxi typecheck`, `tsc -p tsconfig.tools.json` (web and plugin-kb) and `biome check` clean.

Approving.
