Reviewed at high effort against dev, with the renderer exercised directly over
about 25 inputs — code spans, fences, links, images, autolinks, tables,
headings, blockquotes, adjacent and repeated references — and the client
grammar run side by side with core's `extractProseRefs` over the test corpus
plus unicode lead characters, `#t4mwvm2j-slug` and uppercase. No divergence,
no nested anchor, and the `level` bookkeeping in the rebuilt token stream is
right.

Three findings. Two are fixed in the second commit and each has a test that
fails without it: an escaped reference was linked anyway, because the rule ran
after `text_join`; and the resolver navigated on a lookup nobody was waiting
for any more, which took somebody who pressed Back and yanked them forward
with no way back.

The third I chose not to fix here, and the reasoning is worth recording since
it is a judgement rather than an oversight. Following a reference in
`SpecEditor`'s preview discards the draft being previewed. That is real, but
this app guards no exit from an editor — the sidebar loses the same draft to
the same click — so the narrow fix would be a special case in a shared
component for one of many doors. I implemented it anyway to see, and the e2e
stack showed it is worse than the problem: the token is kept in
`sessionStorage` deliberately, so the new tab signed in again rather than
landing on the reference. Backed out, and filed as #x8otoby0.

Also checked: DOMPurify keeps `class`, so `nav-reference` survives sanitising;
the error codes the resolver branches on are what the server actually sends
(`WRONG_KIND` carries the kind, which is what makes the common path one
request); the probe queries raise no toast, since the error link only toasts
mutations; and the static host's `/200.html` fallback covers the new route.

Approving. 342 unit tests, 139 end-to-end against a real browser, server and
repository, and typecheck and lint clean.
