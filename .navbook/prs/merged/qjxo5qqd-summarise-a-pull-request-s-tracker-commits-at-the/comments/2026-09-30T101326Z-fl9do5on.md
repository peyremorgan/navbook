Adversarial self-review of revision 2, after the rebase onto `dev` at 2208dea. The fixes are in `fdf41da`.

**Rebase.** Features moved into `@navbook/plugin-kb`, so core's `SPECS_DIR` is gone. The summariser now knows issues and pull requests only. `kind` reuses the schema's `Kind` enum, and a commit that touches only a plugin's files is shown by its subject. The conflicts were in the resolver imports and the generated code; both codegens were rerun.

**Found and fixed:**

1. `activity.total` counted the summarised commits (at most 250), not the range.
2. The activity's patches were unbounded: a commit importing thousands of comments would send all of them. The activity now spends the diff's inline budget. A withheld tracker file says it is too large, because no "Load diff" can answer it there. The first version of that fix hid "Load diff" on every withheld code file too, because Vue reads an absent boolean prop as `false`. The e2e test "withholds a large file" caught it, and the prop now defaults to `true`.
3. A parentless commit in the range failed the whole query. It is now diffed against the empty tree, and an unreadable one is listed by its subject alone.
4. A deletion listed every removed field as a fact.
5. Map-valued keys (`merged`, plugin data) were compared by their displayed part only.
6. A failed diff showed a second error line for the activity.

**Checked and left as is:**

- A new revision needs a reload to refresh the activity, the same as the diff (`cache-first`).
- Issue and PR IDs share one space, so the subject's ID picks the record without its kind.
- The empty-tree SHA is SHA-1's. A SHA-256 repository falls back to "listed by its subject".
